## 🏛️ Executive Summary: The Anatomy of Disciplined Agentic Engineering

The `observations/` directory records observations of autonomous software engineering performed by AI coding assistants. Drawing on autonomous sessions, pull requests, and refactoring cycles in [`devops-cli`](https://github.com/dan-petty/devops-cli) and [`vibes`](https://github.com/dan-petty/vibes), plus illustrative scenarios and Python simulations, these studies describe how stochastic language models behave under engineering constraints. Each study's Key Metric line or section 5 says what was measured and what was not.

The fundamental insight across all 76 observations is simple yet profound:

> **Stochastic token generation without mechanical boundary oracles collapses into structural entropy. Unbounded models drift into procedural spaghetti, hallucinated tool arguments, orphaned background processes, and brittle heuristic traps. When bounded by deterministic AST invariants, formal contracts, and closed-loop feedback engines, agent output can be checked by machine, and the checks catch failures that prompts alone let through.**

1. **`devops-cli`**: Foundational operational, syntactic, and governance discoveries from building a production-grade infrastructure CLI.

3. **`systems`**: Distributed systems dynamics including OpenTelemetry tracing waterfalls, test runner latency optimization, polling file watchers, Valkey L2 caching, and rootless container isolation.

## 🔬 The Eight Unifying Architectural Theses

When analyzed collectively, the 76 case studies coalesce into eight core engineering theses that define disciplined agentic software development:

> 🔬 **Empirical Grounding & External Literature**: For formal cross-examination against external peer-reviewed software engineering research (McCabe, Shepperd, Fenton, Nagappan, Le Goues, Sharma, Liu), counter-evidence analysis, and code samples examining where invariants succeed and where they break down, see [**Empirical Foundations & Critical Synthesis of Agentic Engineering**](../docs/EMPIRICAL_FOUNDATIONS.md).

### 1. Deterministic Mechanical Oracles Over Prompt Faith
Stochastic language models cannot self-evaluate architectural complexity, nesting depth, type safety, or security boundaries purely through prompt instructions. Relying on "be careful not to write complex code" invariably fails.
- **AST Invariants**: Mechanical parsers (`ast.walk`, `ast.NodeVisitor`) check hard ceilings ($M \le 10$, depth $\le 5$). A ceiling holds only where a gate blocks it: in October 2026 `devops-cli` blocked nesting depth but only reported complexity.
- **Executable Living Contracts**: TDD establishes an objective physical runtime oracle that models must satisfy before moving forward.
- **Compile-Time Type States**: Affine type systems (Rust) and discriminated unions (TypeScript) turn calls that are invalid in the current state into build errors.

### 2. Negative Contracts, Prescriptive Feedback & Epistemic Hygiene
Permissive schemas and vague error messages induce degenerative agent retry spirals.
- **Negative Schema Assertions**: Rejecting undeclared parameters (`additionalProperties: false`) forces the model to respect exact API contracts.
- **Prescriptive Error Prompts**: Rather than returning raw tracebacks, mechanical validators synthesize structured instructions detailing allowable fields, so the model can correct the call on the next turn (no correction rate was measured).
- **Anti-Brittle Closed Domains**: A written rule restricts pattern matching to exhaustive domains (RFCs, official language grammars, public registries like Mozilla PSL) and forbids ad-hoc partial lists; such lists still appeared after the rule (issue #431).

### 3. Process Group Containment & Zero-Trust Sandboxing
Model-generated code is untrusted code. Direct host execution invites orphaned process accumulation, credential theft, and denial-of-service.
- **POSIX Process Groups**: Allocating a dedicated process session (`start_new_session=True`) lets `os.killpg(os.getpgid(pid), SIGTERM)` reach every descendant that stays in the process group; a descendant that calls `setsid` escapes it.
- **Container Controls**: Eight controls modeled on the CIS Docker Benchmark (read-only rootfs, `--network none`, `--cap-drop ALL`, non-root UID 1000, 512MB RAM cap, 100 PID limit, bounded output) reduce what generated code can reach on the host. The example checks the declared policy; it does not check that the runtime is rootless.

### 4. The Closed-Loop Feedback Inversion Dynamic
Static linting is historically reactive—it barks only after rules are violated. Autonomous agent engineering requires an **inverting feedback dynamic**:
- **Phase 1 (Reactive Remediation)**: Fix active blockers, failing tests, and syntax errors with 100% priority.
- **Phase 2 (Proactive Quality Elevation)**: When health reaches 100.0/100, the engine shifts focus to proactive headroom ($M \in [7, 10] \to M \le 6$), complete docstring/type coverage, and test latency optimization.
- **Phase 3 (Continuous Self-Hardening)**: Every struggle, friction point, or defect is systematically codified into [`AGENTS.md`](../AGENTS.md) and [`docs/ROADMAP.md`](../docs/ROADMAP.md) to reduce recurrent failure modes across future sessions.

### 5. Multi-Agent Concurrency & Worktree Spatial Isolation
Running multiple agents concurrently against a shared codebase creates catastrophic workspace contention, SQLite unlink races, and rebase live-locks unless guarded by strict architectural separation:
- **Spatial Isolation**: Separate git worktrees (`git worktree add`) keep concurrent file edits out of peer test runs; the object store and refs stay shared.
- **Partitioned Data Tiers**: Scoping cache directories (`.data/agent/<id>`) isolates SQLite coverage databases, removing file unlinking races during parallel test execution.
- **FIFO Pull Request Shepherding**: Processing PRs oldest first reduces rebase churn; no rate was measured.

### 6. Invariant-Grounded Recursive Self-Improvement & Post-Harness Relevance
When code synthesis velocity approaches infinity, static codebases face exponential relative decay. Autonomous self-evolution is mandatory, but succeeds only when anchored to asymmetric mechanical invariants (an analogy to $P$ vs $NP$), monotonic CEGIS-style constraint accumulation, and continuous outward conformance probing.
- **Asymmetric Verification**: Checking code against invariants ($M \le 10$, depth $\le 5$, coverage $\ge 90\%$) is cheap and deterministic; writing code that passes them is not. This is an analogy to $P$ vs $NP$, not an instance of it.
- **Monotonic Constraint Accumulation**: Every discovered defect becomes a permanent regression case, so a change that brings it back fails; no oscillation rate was measured.
- **Outward Conformance Equilibrium**: Inward-facing linters are balanced with outward landscape telemetry, escaping the defect-shaped myopia trap and driving continuous feature innovation.

### 7. Dual First-Class Consumers & Bi-Directional Cybernetic Co-Evolution
Software must expose a synchronized dual-surface interface serving both human intuition (UX) and agent precision (AX). When agents measure and score software impedance (AX) alongside software scoring agents ($S_{\text{Agent}}$), the resulting bi-directional feedback is designed to drive a co-evolutionary improvement loop; no benchmark has measured it:
- **Dual-Surface Interface**: High-level human teleology, observability, and cryptographic attestation paired with strict negative schemas (`additionalProperties: false`), constant-time AST symbol graphs, and structured CEGIS error vectors.
- **Bi-Directional Scoring Matrix**: Evaluating repository usability via Diagnostic Actionability ($DAI$), Interface Friction ($IFI$), and Cognitive Impedance ($CIM$).
- **Co-Evolutionary Ratchet**: In the target design, a low AX score turns the recorded friction into a refactoring task that hardens the interface. No benchmark measures the loop.

### 8. Biological Autopoiesis, Homeostatic Damping & Thermodynamic Metabolism
Autonomous software systems executing continuous background loops behave, by analogy, like autopoietic dissipative structures. Unconstrained self-healing induces hyper-metabolic churn on transient noise and economic starvation on rented cloud APIs.
- **Inward Afferent Telemetry**: Distributed traces and metrics serve as sensory afferents triggering self-healing only when crossing hysteresis deadbands ($\pm \delta$).
- **Cellular Apoptosis**: Ephemeral subagents, leaking file descriptors, and deadlocked processes are terminated cleanly via guarded POSIX process groups (`os.killpg`), preventing host exhaustion.
- **Local Inference ("Autotrophy")**: Running continuous repair loops on local hardware cuts the marginal token cost to electricity and hardware wear. Landauer's bound is far below the energy GPUs use, so the saving comes from pruning work, not from thermodynamics.
